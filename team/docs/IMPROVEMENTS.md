# 팀 개선 과제 정리

2026-11-20 · 대상: 팀원 · 브랜치 `prototype` · 기본 기능(브라우저 ↔ 상담원 서버 ↔ 함수) 연결 확인 후 정리

## 먼저: 지금 들리는 어색함은 대부분 임시 모델 때문입니다

브라우저 테스트 화면에서 시험한 구성은 공식 모델이 아니라 **임시 대체물**입니다.

| 역할 | 지금 시험한 것 | 대회 공식 모델 (11/21 키 제공) |
|---|---|---|
| 듣기 (STT) | 로컬 Whisper `faster_whisper` | Soniox `stt-rt-v4` |
| 답 만들기 (LLM) | gpt-4.1 | gpt-5.4-mini |
| 말하기 (TTS) | Windows 기본 음성 `sapi` (기계음) | Gemini 2.5 Flash TTS |

- gpt-4.1은 **답할 문장만 만드는** 모델입니다. 단어·음소 인식(STT)과 목소리(TTS)와는 관계가 없습니다.
- 음질과 인식 정확도는 **11/21 공식 키로 다시 들어 보고** 판단합니다. 공식 모델 3종은 아직 한 번도 실제로 호출하지 않았습니다.

## 1. 말 끝 판단과 말 끊기 (턴 주고받기)

| 문제 | 지금 상태 | 근거 |
|---|---|---|
| 완결된 문장 뒤에 쉬면 끼어듦 ("문의 좀 드릴게요." … 1.3초 … "주문번호는…") | 남아 있음. 그 문항 **속도 0점** | ISSUES #1, K05 |
| 문장이 끝난 뒤 쉬었다 이어 말함 | 침묵 길이로는 못 막음 | ENDPOINTING.md KO7 |
| 번호를 끊어 부르기, 번호 앞에서 쉬기 | 1.3초 이상 기다려야 막힘 → 그만큼 느려짐 | ENDPOINTING.md KO5·KO9 |
| 전화 음질·잡음에서 말 끝을 일찍 판단 | 가짜 신호에서 끼어듦 1/3 | ISSUES #13 |
| 고객이 상담원 말을 끊음 (barge-in) | 지원 안 함. 서버가 응답 중 입력을 무시 | devui/README.md |
| 대화 종료 ("감사합니다, 끊을게요") | 따로 판단하지 않음. 프롬프트에 맡김 | |

정할 것
- `AGENT_EOU_MODE=vad`(지금 방식)와 `soniox_stream`(Soniox `<end>` 신호)을 같은 음성 18개(`team/data/endpoint_ko`)로 비교한 뒤 기본값을 정합니다. 공식 키가 필요합니다.
- "끼어듦 0"과 "빠른 첫 소리" 중 무엇을 우선할지 정합니다. 끼어들면 그 문항 속도가 0점이므로, 조금 늦더라도 기다리는 쪽이 대체로 유리합니다.
- **운영진 문의**: 사용자 경험 심사에서 말 끊기나 여러 턴 대화를 직접 시험하는지. 공식 측정은 한 문항에 고객 발화 1개라서 시스템 점수에서는 barge-in을 재지 않습니다.

필요한 데이터: 공식 연습 음성, 팀원 실제 녹음(`team/data/holdout_ko`), 쉼·정정·끊어 부르기 사례.

## 2. 음성 인식 (STT)

| 문제 | 근거 |
|---|---|
| 주문번호 뒤 조사를 숫자로 붙임 ("일공공일이에요" → `10012`) | ISSUES #3, 브라우저 시험 |
| "데모" 생략, 번호 정정 처리 | `team/tests/test_gate_edges.py` 알려진 한계 3건 |
| 잡음만 들어가면 Whisper가 문장을 지어냄 ("한글자막 by …") | 로컬 Whisper만 해당. 필터 추가함 |
| 마이크 거리·장치 영향 (웹캠 마이크는 멂, 잡음만 들어오는 입력 장치) | 브라우저 시험. 화면에 "마이크 자동 찾기" 추가함 |

개선 방향
- 공식 Soniox로 같은 문장을 다시 시험합니다(1순위).
- 인식된 숫자를 코드에서 정리하는 규칙을 둡니다: 조사 분리, 정정이 있으면 마지막 값 사용.
- 번호가 불확실하면 복창해서 확인합니다. 응대 품질과 함수 점수 모두에 걸립니다(LLM_BACKLOG F2, R4).
- 관문의 숫자 정규화를 STT 규칙과 함께 맞춥니다(LLM_BACKLOG G2).

## 3. 음성 합성 (TTS)

| 과제 | 비고 |
|---|---|
| 공식 Gemini TTS 실제 음질·속도 확인 | 미검증. 24 kHz → 16 kHz 변환 가정 |
| 목소리·말투 선택 (`AGENT_GEMINI_TTS_VOICE`, `AGENT_GEMINI_TTS_STYLE`) | 기본 Kore. 스타일 문구는 소리 내어 읽힐 수 있어 시험 필요 |
| 번호 읽기 형식 통일 ("공일공 공공공공 일이삼사"와 "01000001234"가 섞임) | LLM_BACKLOG R7 |
| 문장을 나누는 단위가 억양에 주는 영향 | 첫 조각 쉼표 끊기(꺼져 있음)는 속도에 유리하지만 억양이 어색할 수 있음 |
| 스트리밍 사용 여부 (`AGENT_GEMINI_TTS_STREAM`) | 첫 소리 지연과 직결 |

## 4. 답변 품질 (LLM)

- 공식 모델은 **gpt-5.4-mini**입니다. gpt-4.1로 맞춘 프롬프트는 다시 시험합니다.
- 보류 목록 27건([LLM_BACKLOG.md](LLM_BACKLOG.md)). 주요 항목:
  - 관문 안내 문구가 답에 새어 나옴 (R1)
  - 이미 받은 정보를 다시 물음 (R8)
  - 같은 문장 반복 (R9)
  - 함수 인자에 없는 조건을 말함 (R10)
- 전화 상담에 맞는 답 길이와 말투를 정합니다: 짧게, 한 번에 하나만 묻기.
- 건강 이상·인계 응대는 공식 매뉴얼이 나와야 정할 수 있습니다(R6, F4).

## 5. 속도 (시스템 점수의 30%)

- 예전 실측(gpt-4.1, 통합 전)은 첫 소리 p50 3.34초로 6초 이내 득점 구간입니다(REPORT.md). 통합한 prototype을 실제 모델로 잰 적은 아직 없습니다.
- 단계별 p50: 말 끝 판단 1.15초 · LLM 첫 글자 1.15초 · 첫 문장 TTS 0.93초. 함수 문항은 LLM을 두 번 부릅니다.
- 줄일 후보:
  - 조회 중 멘트(`AGENT_TOOL_ACK`): 채움말도 첫 소리로 인정되지만, 함수 문항은 조회 뒤 답 점수와 평균이라 효과가 절반
  - Gemini 스트리밍
  - 관문에 막혔을 때 추가 LLM 호출 없애기 (LLM_BACKLOG L1)
- 효과는 공식 모델로 같은 조건에서 켰을 때와 껐을 때를 비교해 확인합니다([LATENCY.md](LATENCY.md)).

## 6. 사용자 경험 (50점, 정성 평가)

배점이 가장 큽니다. 위 과제 중 체감에 영향이 큰 것:

- 끼어들지 않기
- 번호를 정확히 알아듣기, 못 알아들었을 때 자연스럽게 다시 묻기
- 자연스러운 목소리
- 같은 말 반복하지 않기
- 할 수 없는 일(인계 등)을 됐다고 말하지 않기

대회의 세부 평가 기준을 팀이 함께 읽고 위 과제에 우선순위를 매깁니다.
