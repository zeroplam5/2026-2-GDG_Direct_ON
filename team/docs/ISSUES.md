## 상세

### 1. 완결 문장 뒤 긴 쉼에서 끼어듦 (K05)
- 근거: REPORT 세트 B, 팀 1차 끼어듦 2/24가 모두 K05. `team/runs/bench3_gpt-4.1` 에서는 K05 3회 모두 끼어듦
- 문장: "배송 문의 좀 드릴게요." (1.3초 쉼) "주문번호는 데모 이 공 공 이 입니다."
- 원인: "드릴게요."가 완결 문장으로 판정 → `complete_silence_ms=1100`에 말 끝 확정 → 실제 쉼 1.3초보다 먼저 응답
- 같은 1.3초 쉼이라도 K04("주문번호가")는 미완결로 판정돼 1.8초까지 기다려 통과
- 재현: `python -m team.scripts.bench --configs default_1100_1800 --repeats 3 ...` 후 `per_case_first_sound`의 K05
- 회의에서 나온 방안: 완결 대기 1.4초 이상(모든 문항 0.3초 이상 느려짐) / 예고성 문장("문의 좀 드릴게요")을 미완결로 처리

### 2. 첫 소리 p50 3.34초
- 근거: REPORT, gpt-4.1 단계별 p50: 발화 종료 판단 1.15초 · LLM 첫 텍스트 1.15초 · 첫 문장 TTS·전송 0.93초
- STT는 무음 400ms에 미리 시작해서 확정 후 대기 0초. **손님이 다시 말하면 미리 돌린 STT는 취소되고, 확정 때는 최신 음성 결과만 씀** (코드 `session.py` resume 처리 + 기존 테스트 `test_mid_utterance_pause_with_incomplete_text_does_not_interrupt`로 확인)
- 함수 문항은 LLM을 두 번 불러 더 느림
- 관련 제안: `feature/latency`(조회 중 멘트, 기본 꺼짐). 공식 모델(Gemini TTS)로 다시 재야 함

### 3. 주문번호 뒤 조사를 숫자로 붙임
- 근거: REPORT "STT가 '1001이에요'를 `10012`로 붙여 쓴 경우"
- 영향: 조회 실패 → "일치 내역 없음" 안내 (지어내지는 않음)
- 확인할 것: 공식 STT(Soniox)에서도 같은지, "인식한 번호가 불확실할 때 다시 확인" 설계 (회의 메모)

### 4. LLM이 잘못된 인자로 함수 호출
- 근거: REPORT 세트 B gpt-4.1 함수 16회 중 불일치 4회 = 의도된 not_found 3 + `DEMO10001` 1
- 영향: 함수 점수 (맞는 번호로 호출해야 정답)

### 5. 확인 없이 접수 (gpt-5)
- 근거: REPORT 응답 내용 관찰, K07 콜백 전 번호 확인 gpt-5 0/3
- 회의 방안: 변경·접수 함수는 프롬프트에만 기대지 말고, 실행 직전에 필수 정보·확인 상태를 코드에서도 검사
- 현재 코드(`tools_client.py`): **필수 인자 검사는 이미 있음.** 빠지면 함수 서버로 보내지 않고 `missing_arguments`를 LLM에 돌려줌. **손님이 확인했는지(확인 상태) 검사는 없음** → 추가 필요

### 13. 전화 음질에서 말 끝 판단이 달라짐
- 근거: `make_testset` 시험 중 발견 (2026-11-19). 가짜 말소리(기본 주파수 180Hz) 3개를 전화 음질로 바꿔 측정
  | 버전 | 첫 소리 (측정기) |
  |---|---|
  | 원본 3개 | 1.91~1.93초 |
  | 잡음 SNR 15dB 3개 | 1.87~1.89초 |
  | 전화 음질 3개 | 0.93초 / 1.35초 / **끼어듦** |
- 원인 추정: 전화 대역은 300Hz 아래를 잘라 내서 소리가 작아지고, 음량 기준이 섞인 발화 감지(`webrtc` + 에너지·잡음 하한)가 말소리를 일찍 놓침
- 한계: 가짜 신호는 낮은 소리 위주라 실제 목소리보다 영향이 과장됐을 수 있음
- 확인: holdout 녹음을 `--variants phone`으로 만들어 원본과 비교 (`team/data/holdout_ko/README.md`)
