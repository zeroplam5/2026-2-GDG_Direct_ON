# 스타터킷 v2 검토와 콜백 응답 실험 (2026-11-21)

운영진이 새로 준 스타터킷(`starter_v2/`, 저장소에는 올리지 않음)을 기존 키트와 비교했습니다. 키트 내용을 코드에 옮기지 않고, 거기서 나온 주제를 우리 상담원으로 실험했습니다.

요약
- v2는 우리가 [REPORT.md](REPORT.md)에서 신고한 데모 음성 문제를 고친 버전입니다. 프로토콜·함수·채점표는 같고, 우리 상담원은 수정 없이 통과합니다.
- 콜백 실험에서 공식 모델 gpt-5.4-mini가 **함수 결과에 없는 "내일 오전 열 시 접수"를 4번 중 2번** 말했고, **전화번호를 틀리게 되읽었습니다(2건)**. 프롬프트에 이미 금지 규칙이 있었는데도 일어났습니다.
- 코드 검사 4가지를 추가한 뒤 같은 실험에서 공식 모델의 번호 오류는 0건, 시간 약속은 1건으로 줄었습니다. 남은 1건은 걸러 낼 단어 목록을 보강해 막았고, 문장 단위 테스트로 확인했습니다.

## 1. v2에서 바뀐 것

| 영역 | 기존 | v2 |
|---|---|---|

| `run_eval.py`, `score_demo.py` | 파일 인코딩 미지정 (Windows에서 `PYTHONUTF8=1` 필요) | `encoding="utf-8"` 지정. 측정 로직·점수표는 그대로 |
| `example_server --demo-tool` | `get_order_info(DEMO1001)` | `request_callback(발신자 번호)`를 확인 없이 호출 |
| README | "공식 채점 395문항 / 응대 50%·함수 20%·속도 30%" | 삭제. "이 ZIP만으로 재현할 수 없습니다"만 남음 |

v2 측정기와 새 데모 음성으로 우리 상담원(faster_whisper + scripted + tone)을 돌려 보니 3건 모두 끼어듦 없이 첫 소리가 1.2초 안팎이었고, DEMO2는 `get_order_info(DEMO1001)`를 정확히 불렀습니다.

팀 결정
- **확인 먼저 정책은 유지합니다.** v2 예시 서버는 확인 없이 콜백을 부르지만, 통신 시연용 예시일 뿐 정답 기준이 아니라고 봤습니다.
- 키트 내용을 코드에 옮기지 않고, 거기서 나온 주제를 실험합니다.
- v2 데모는 3문항뿐이므로 긴 쉼·정정을 담은 팀 세트(`practice_ko` 등)도 계속 씁니다.
- 아직 손대지 않은 것: README에서 점수 비율이 사라졌지만, devui 예상 점수(응대 50·함수 20·속도 30)는 그대로 둡니다. 공식 안내가 나오면 다시 봅니다.

## 2. 실험 방법

| 항목 | 내용 |
|---|---|
| 서버 | `team.agent.server --stt faster_whisper --llm openai_compat --llm-model <모델> --tts sapi --log-text` |
| 측정기 | `starter_v2/eval/run_eval.py`, `--concurrency 1` |
| 모델 | gpt-4.1(팀 기본), gpt-5.4-mini(공식) |
| 반복 | 모델마다 2회 |
| 음성 세트 | v2 DEMO1–3 · 콜백 2턴째 `team/data/callback_ko`(DEMO3C, DEMO3T) · 팀 연습 `team/data/practice_ko`(K01–K08) |

DEMO3 한 턴만으로는 관문이 확인 질문만 하므로, 함수 호출 뒤의 답을 보려고 2턴째 문항을 만들었습니다(`team.scripts.make_callback_audio`). 이전 이력은 "고객: 내일 오전에 다시 전화 좀 부탁드려요." → "상담원: 01000001234 번호로 상담원 연락을 접수해 드릴까요?"입니다.
- **DEMO3C**: "네, 그 번호로 해 주세요."
- **DEMO3T**: "네, 그 번호로 내일 오전 열 시쯤으로 부탁드려요." 함수 결과(`{"status":"ok","message":"상담원 콜백 접수"}`)에 시간이 없으므로 시간 약속을 유도하는 문항입니다.

## 3. 결과 (변경 전)

| 문항 | gpt-4.1 | gpt-5.4-mini |
|---|---|---|
| DEMO2 | 2/2 `DEMO1001` 정상 | 2/2 정상 |
| DEMO3 1턴 | 2/2 호출 없이 확인 질문 | 2/2 호출 없음. 1회 **번호를 "일공일공 공공공일 이공삼사"로 잘못 읽음**, 2/2 "내일 오전으로 접수"를 미리 약속 |
| DEMO3C | 2/2 정상 호출, 시간 약속 없음 | 2/2 정상 호출. 1회 **"내일 오전에 다시 전화 부탁하신 내용으로 접수되었습니다"** |
| DEMO3T | 2/2 호출 없이 "시간 지정은 반영되지 않는다"고 알리고 재확인 | 2/2 호출. 1회 **"내일 오전 열 시쯤으로 확인해 두었습니다"** |
| K06 (발신자 정보 없음) | 1회 **"010-1234-5678이 맞는지"** — 없는 번호를 지어냄 | 정상 |
| K07 | 정상 | 1회 **번호를 "010 공일공공 일이삼사"로 잘못 읽음** |
| K05 (완결문 뒤 긴 쉼) | 2/2 끼어듦 | 2/2 끼어듦 |
| K01–K04, K08 | 인자 모두 정확, 정정(K08) 정상 | 같음 |

원인
1. **틀린 번호는 출력 검사에 걸리지만 그대로 나갔고, 기록도 없었습니다.**
   - 문제 문장을 출력 검사에 다시 넣어 보면 3건 모두 "근거 없는 숫자"로 잡힙니다. 그런데 검사가 `log` 모드라 문장이 그대로 나갑니다.
   - 대회용 서버는 metrics에 정해진 항목만 쓰기 때문에, 관문 판정과 검사 결과가 남지 않았습니다.
2. **시간 약속은 기존 검사로 잡을 수 없었습니다.** "열 시"는 고객이 직접 한 말이라 근거가 있는 숫자로 통과합니다. "내일 오전 … 접수되었습니다"에는 숫자가 없습니다.
3. 프롬프트에는 이미 "인자에 없는 조건이 반영됐다고 말하지 않는다"와 "전화번호를 추측하지 않는다"가 있었습니다. **프롬프트 규칙만으로는 막히지 않습니다.**

## 4. 바꾼 것

| 변경 | 위치 | 내용 |
|---|---|---|
| 기록 추가 | `session.py` | metrics에 `gate`(함수 이름·허용 여부·사유, 인자 없음), `blocked_reply`, `output_flags`를 남김. 검사가 잡은 값은 `--log-text`일 때만 |
| 전화번호 되읽기를 코드가 담당 | `policy.py` 함수 규칙 문장, 프롬프트 33행 | `confirm_template`이 있는 접수 함수는 모델이 말없이 바로 호출 → 관문이 막음(함수 서버에는 안 감) → 코드가 실제 인자 값으로 확인 질문. 확인 먼저 정책은 그대로 |
| 번호 차단 (전화번호·주문번호로 한정) | `output_guard.py` | 대화에 나온 적 없는 9자리 이상 숫자나 영문에 붙은 숫자(`DEMO1002`)가 있으면 "번호를 정확히 확인하기 위해 한 번 더 말씀해 주시겠어요?"로 바꿈. 가격·기간 같은 다른 숫자는 지금처럼 기록만 |
| 시간 확정 문장 차단 | `output_guard.py`, 단어 목록은 `practice_rules.json`의 `output_check` | 시간 표현 + 접수·연락·전달 표현이 있고 함수 결과에 시간 값이 없으면 "희망하신 시간은 지금 확정해 드릴 수 없습니다."로 바꿈. 부정문("반영되지 않았습니다")은 통과 |
| 시간 제안 질문에 안내 | 같음 | 질문은 막지 않고 앞에 "희망 시간은 확정되지 않았습니다."를 한 턴에 한 번 붙임 |
| 설정 | `config.py` `output_guard_strict` | 기본 `"ids,time"`. `""`이면 바꾸기 전처럼 기록만 |

테스트: 모델이 실제로 한 문장들로 [test_output_claims.py](../tests/test_output_claims.py)를 만들었습니다. 막아야 할 문장과 통과해야 할 정직한 문장을 모두 넣었습니다. 전체 105개 통과(3개는 원래 실패로 표시된 테스트).

## 6. 남은 것

- **gpt-4.1은 코드가 확인 질문을 하는 방식을 따르지 않을 때가 있습니다.** K07 2/2에서 번호 없이 스스로 물었고, 그 경우 대화가 한 턴 늘어납니다. 공식 모델이 gpt-5.4 계열이라 넘어가기로 했습니다.
- **K05(완결문 뒤 긴 쉼) 끼어듦**은 그대로입니다. 말 끝 판정 쪽 과제입니다([ENDPOINTING.md](ENDPOINTING.md)).
- **`first_chunk_min_chars`를 켜면** 질문이 "?" 전에 쉼표에서 잘린 채 검사될 수 있습니다. 그 조각에 시간과 접수 표현이 함께 있으면 질문이 아닌 확정 문장으로 판단돼 바뀝니다. 기본값 0에서는 해당되지 않습니다.
- 시간 판정 단어 목록은 연습용입니다. 공식 함수에 시간 인자가 생기면, 함수 결과에 시간이 담길 때 자동으로 통과하는지 다시 확인해야 합니다.

## 다시 돌리기

```powershell
# 터미널 A: 모의 서버
.venv/Scripts/python -m team.mock.mock_api --port 8100
# 터미널 B: 상담원 (모델만 바꿔 가며)
.venv/Scripts/python -m team.agent.server --port 9000 --stt faster_whisper --llm openai_compat --llm-model gpt-5.4-mini --tts sapi --log-text --metrics team/runs/cb/metrics.jsonl
# 터미널 C: 콜백 2턴째 세트 (팀 세트는 --cases/--audio를 practice_ko로)
.venv/Scripts/python eval/run_eval.py --server ws://127.0.0.1:9000 --cases team/data/callback_ko/cases.jsonl --audio team/data/callback_ko/audio --mock http://127.0.0.1:8100 --out team/runs/cb/r1 --concurrency 1
```
metrics의 `user_text`, `reply_text`, `gate`, `blocked_reply`, `output_flags`를 보면 STT, 함수 판정, 검사 결과를 한 줄에서 확인할 수 있습니다. 음성은 `team.scripts.make_callback_audio`로 다시 만들 수 있습니다.
