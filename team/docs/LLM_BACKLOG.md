# LLM·함수 세부 개선 기록 (보류 목록)

구조를 먼저 점검하고, 세부 개선은 여기에 모아 두었다가 꺼내 쓴다.

기준 측정 (2026-11-19, OpenRouter 경유 gpt-5.4-mini, effort none, 관문 켬): `llm_probe --suite gate --repeat 3` → 27/27 기대와 일치.
관문이 실제로 막은 호출 9회(G02·G03·G04 각 3/3), 막힌 뒤 추가 응답 +1.3~1.9초. 관문 없이 K07은 3/3 확인 없이 접수.

규칙 한 곳으로(S1) 뒤 같은 측정: 27/27. 모델이 잘못 부른 호출이 9회 → 2회로 줄어(G02 1회, G04 1회) 나머지는 모델이 스스로 확인 질문을 함.
자동 생성된 [함수 실행 규칙]이 효과가 있었고, 관문은 남은 2회를 막음. 두 번째 모델 호출(지연)도 그만큼 줄어듦.
상태: **보류** = 아직 손대지 않음 · **11/21** = 공식 자료가 나와야 정할 수 있음 · **완료** = 반영됨.
담당 범위: LLM 프롬프트, 함수 호출, 실행 전 관문(`team/agent/gate.py`), 확인 도구(`team/scripts/llm_probe.py`).

## 구조 (세부보다 먼저 점검하는 것)

| # | 내용 | 상태 |
|---|---|---|
| S1 | 규칙을 한 곳으로: 함수 실행 규칙·인계 신호·동의 단어를 `prompts/practice_rules.json` 하나에 모으고, 프롬프트의 [함수 실행 규칙]은 그 표에서 자동 생성. `AGENT_PACK_DIR`로 묶음 전환. 11/21 체크리스트는 `prompts/README.md` | 완료 (2026-11-19) |
| S2 | 출력 검사 자리: `team/agent/output_guard.py`. 모델 문장마다 TTS 전에 검사. 첫 검사는 "프롬프트·고객 말·함수 결과 어디에도 없는 숫자". 기본 `AGENT_OUTPUT_GUARD=log`(기록만), `block`이면 `unverified_fallback` 문장으로 바꿈 | 완료 (자리만. 검사 내용 확장은 F3) |
| S3 | 막혔을 때 두 번째 길: 규칙표의 `confirm_template`이 있으면 모델을 다시 부르지 않고 그 확인 문장으로 바로 답함(지연·관문 문구 새어 나옴 해소). 없으면 모델이 답함 | 완료 |
| S4 | 문맥 배치: 시스템 메시지 하나 안에서 고정 내용(지침·함수 규칙)을 앞에, 통화 정보(now·발신자·이력)를 끝에. 처음에는 시스템 메시지를 둘로 나눴는데 글 답변 6회 중 5회가 같은 문단을 두 번 써서 하나로 합침. 하나로 합친 쪽 비교는 6회 모두 함수 호출이라 결론이 안 났고, 합친 뒤에도 반복이 나와서 R9로 따로 막음 | 완료 |
| S5 | 끝까지 시험대: `llm_probe --full`. 실제 대화 루프(관문·막힘 처리·출력 검사)를 돌리고 모의 데이터로 함수를 실행해 결과 뒤의 답까지 출력 | 완료 |
| S6 | 막힌 회차에 모델이 이미 확인 질문을 말했다면 그 턴을 끝내 같은 질문을 두 번 하지 않음 | 완료 |

| R4 | 번호를 다시 읽게 하는 대신 조회 결과로 확인 ("6월 1일 구매하신 ○○ 맞으신가요?") | 본문 D (네이블 시연) | 보류 |
| R5 | 대기 멘트를 쓴다면 내용 있는 문장으로, 매번 다르게 | 요약 5, 본문 A2·D | 보류 |
| R6 | 건강 이상 대응이 엇갈림: 프롬프트는 "복용 중단 지시 금지", 조사는 "섭취 중단 권고 + 인계" | 연습 프롬프트 37행, 요약 4 | 11/21 |
| R7 | 번호 읽기가 제각각: "01000001234", "공일공 공공공공 일이삼사", "010공공공공 일이삼사"가 섞임. 응답 문장 단계에서 한 형식으로 맞추기(TTS 정규화와 함께) | 3회 반복 G03·G08 (2026-11-19) | 보류 |
| R8 | 이미 있는 정보를 다시 물음: 보류 응답에서 "연락받으실 번호와 원하시는 시간을 말씀해 주세요", 발신자 번호가 있는데 "다시 전화받으실 번호를 말씀해 주시면" | G06 2회차, S1 뒤 G03 2회차 | 보류 |
| R9 | 한 응답 안에서 같은 문단을 두 번 씀 ("…될까요?\n\n…될까요?"). 원본 스트림 확인 결과 모델(또는 OpenRouter 경유) 자체 출력이고, 시스템 메시지 하나여도 나옴. 출력 검사가 한 턴에서 이미 말한 문장을 버리도록 막음. 원인은 공식 키(OpenAI 직결)로 다시 볼 것 | 27회 중 4회, `--full` 9회 중 2회 | 증상 막음, 원인 보류 |
| R10 | 함수 결과 뒤 답에서 인자에 없는 조건을 말함: 콜백 접수 후 "내일 … 연락드리겠습니다" (콜백 함수에 시간 인자 없음) | `--full` G01 | 보류 |
| R11 | 출력 검사가 잘못 읽은 번호를 잡음: "영 일공 공공 공일 이삼사"(0100001234, 실제는 01000001234). 번호 읽기 형식 통일(R7)과 함께 봐야 함 | `--full` G03, 출력 검사 log | 보류 |

## 지연

| # | 내용 | 근거 | 상태 |
|---|---|---|---|
| L1 | 관문이 막으면 모델을 한 번 더 불러 응답이 약 1.4~1.6초 늦어짐. 정해진 확인 문장으로 바로 답하는 방안 검토 | G02·G04 실행 결과 | 보류 |
| L2 | 프롬프트 캐시에 불리한 구조: 바뀌는 `{now}`가 시스템 프롬프트 첫 줄, 발신자·이력도 시스템 프롬프트 안 | `policy.build_system_prompt` | 보류 |
| L3 | OpenRouter 경유 시간은 OpenAI 직결과 다름. 공식 키로 다시 재야 함 | 연결 확인 (2026-11-19) | 11/21 |
| L4 | 추론 강도 none·low 비교 | `llm_probe --effort none,low` | 보류 |

## 관문 정확도

| # | 내용 | 근거 | 상태 |
|---|---|---|---|
| G1 | 거절·보류 단어 검사가 보수적이라 "아니 그게 아니라 네 맞아요" 같은 말도 막음 | `gate.NEGATIVE` | 보류 |
| G2 | 근거 검사가 부분 문자열이라 `DEMO1001`이 STT의 `DEMO10012` 안에서 근거로 잡힘 | `gate.check` 2단계 | 보류 |
| G3 | 동의 근거 칸이 모델 행동을 바꾸는지: 1회 실행에서는 스스로 확인했지만 3회 반복에서는 3/3 호출 후 관문이 막음. 효과는 약하거나 없음 | G03 1회 vs 3회 반복 | 보류 |
| G4 | 고객이 처음부터 값을 말한 경우(C4)와 행동 선택("취소요", C9)을 바로 실행할지는 매뉴얼이 정함. 규칙표 `confirm` 값으로 조정 | 확인 판정 논의 | 11/21 |
| G5 | 공식 history 형식에 맞춰 `policy.normalize_history` 한 곳만 수정. 상담원 말이 history에 없으면 확인 판정 방식을 바꿔야 함 | history 형식 미공개 | 11/21 |
| G6 | 공식 함수 목록을 규칙표(`practice_tool_policy.json`)에 채우기. 표에 없는 함수는 "접수형 + 확인 필요"로 막힘 | 관문 설계 | 11/21 |
