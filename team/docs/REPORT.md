# DIRECT:ON 음성 상담 AI — 스타터킷 원본 vs 팀 1차 결과 비교

2026-11-19 · 원문: [Claude Docs 문서](https://claude.ai/artifact/Pg16iYz3zsxqc5HMgG31ks) · 실행 방법: [README.md](../../README.md)

> 모든 수치는 스타터킷 측정기로 잰 **연습용 결과**이며 공식 점수가 아닙니다.
> 이전 보고서는 [archive/](archive/)에 보관했고, 이 문서에서는 다루지 않습니다.

## 요약

팀 1차 구성(STT `gpt-4o-mini-transcribe`, LLM `gpt-4.1`, TTS `gpt-4o-mini-tts`)은 스타터킷 원본과 같은 조건에서 끼어듦을 **15/24 → 2/24**로 줄였고, 함수 결과를 실제 응답에 반영했습니다.
대신 첫 소리는 p50 **3.34초**로, 데모 점수표의 만점 구간(1.5초 이내)보다 느립니다.

- 원본은 상담 기능 없이 삐 소리만 내는 통신 예시입니다. 그래서 비교는 통신, 발화 종료 판단, 함수 호출에 한정됩니다.
- 세 LLM 중 gpt-4.1이 속도와 정확성 모두 가장 나아 기본값으로 둡니다. gpt-5는 고객 확인 없이 콜백을 접수했습니다(3/3).
- 스타터킷 데모 음성은 메타데이터가 맞지 않아 속도 비교에 쓸 수 없습니다. 속도 비교는 팀 연습 음성 기준입니다.

## 비교 대상과 측정 조건

두 구성 모두 같은 측정기(스타터킷 원본 `eval/run_eval.py`, 수정 없음)와 같은 음성 세트로 측정했습니다.

| 항목 | 스타터킷 원본 | 팀 1차 |
| --- | --- | --- |
| 상담원 서버 | `example_server/server.py`: 음량으로 발화 종료를 판단한 뒤 삐 소리 1개 | `team/agent`: 발화 종료 판단 → STT → LLM·함수 호출 → TTS |
| 발화 종료 판단 | RMS ≥ 500, 무음 800ms 고정 | VAD로 음성 감지. 무음 400ms에 STT를 미리 시작하고, 문장이 완결돼 보이면 무음 1100ms, 아니면 최대 1800ms에 확정 |
| STT / LLM / TTS | 없음 | `gpt-4o-mini-transcribe` / `gpt-4.1` (비교용 `gpt-5`, `gpt-4o-mini`) / `gpt-4o-mini-tts` |
| 모의 함수 서버 | `mock_tools/mock_api_template.py`: `lookup()` 미구현 | `team/mock/mock_api.py`: 예제 데이터로 `lookup()` 구현 |

- 음성 세트 A: 스타터킷 데모 음성 3개(`data/audio/demo`)
- 음성 세트 B: 팀이 만든 한국어 연습 음성 8문항(`team/data/practice_ko`). 합성음이며 공식 문항이 아닙니다. 문장 사이 쉼, 정정, 인계 후보, 콜백 상황을 포함합니다.
- 환경: Windows 11, CPython 3.12.13, 동시 4세션(측정기 기본값), 세트마다 3회 반복
- 측정기의 속도 점수표(`score_demo.py`)는 데모용이며 공식 점수가 아닙니다.

## 통신·속도 비교

팀 연습 음성(세트 B)에서 팀 1차(gpt-4.1)는 끼어듦을 15/24에서 2/24로 줄였고, 첫 소리는 p50 3.34초입니다.
원본은 아무것도 처리하지 않고 삐 소리만 내기 때문에 빠르지만, 문장 사이 쉼에서 대부분 끼어들었습니다.

**세트 B: 팀 연습 음성 8문항 × 3회**

| 구성 | 끼어듦 | 첫 소리 p50 / p90 (끼어들지 않은 회차) | 응답 완료 p50 | 함수 호출 (일치) | 데모 속도 점수 평균 |
| --- | --- | --- | --- | --- | --- |
| 스타터킷 원본 (삐 소리) | 15/24 | 0.77 / 0.79 s (n=9) | 첫 소리 직후 | 0 | 37.5 |
| 팀 1차 — gpt-4.1 | **2/24** | 3.34 / 3.85 s (n=22) | 5.31 s | 16 (12) | **53.3** |
| 팀 1차 — gpt-4o-mini | 3/24 | 3.64 / 4.16 s (n=21) | 5.40 s | 15 (10) | 44.6 |
| 팀 1차 — gpt-5 | 3/24 | 4.14 / 4.79 s (n=21) | 6.19 s | 18 (14) | 35.4 |

- 원본이 끼어든 문항은 K01·K03·K04·K05·K06입니다. 모두 문장 사이 쉼(약 0.9s)이나 일부러 넣은 쉼에서 800ms 기준에 걸렸습니다.
- 팀 1차에 남은 끼어듦은 모두 K05(완결된 문장 뒤 1.3s 쉼)입니다.
- 데모 속도 점수는 `score_demo.py`의 점수표를 회차마다 적용하고, 끼어든 회차는 0점으로 넣어 평균 낸 값입니다.
- 함수 호출 수에는 일치하는 데이터가 없는 K02 조회 3회가 포함됩니다(의도된 not_found).

**세트 A: 스타터킷 데모 음성 3개 × 3회**

| 구성 | 끼어듦 | 첫 소리 p50 / p90 (측정기 기준) | 함수 호출 (일치) |
| --- | --- | --- | --- |
| 스타터킷 원본 (삐 소리) | 3/9 (DEMO2 전부) | 6.45 / 7.09 s (n=6) | 0 (`--demo-tool`을 켜면 3 (0)) |
| 팀 1차 — gpt-4.1 | 0/9 | 8.87 / 9.13 s (n=9) | 0 |

- 이 세트의 측정기 수치는 **믿을 수 없습니다.** `meta.json`의 발화 종료 시각이 실제 음성과 맞지 않기 때문입니다. 원본의 DEMO2 "끼어듦"과 양쪽의 6~9초 지연은 서버 성능이 아니라 메타데이터 문제입니다(아래 '스타터킷에서 발견한 이상' 참고).
- 팀 1차를 실제 마지막 음성 기준(에이전트 내부 지표)으로 재면 첫 소리는 p50 2.93s / p90 3.89s입니다.

## 함수 호출과 모의 서버

원본 모의 서버는 모든 요청에 `not_implemented`를 돌려주므로, 원본 구성에서는 어떤 함수 호출도 일치(`matched`)하지 않습니다.
팀 1차는 예제 데이터와 일치하는 요청에 기록된 결과를 돌려주고, 그 결과를 응답에 반영합니다.

| 항목 | 스타터킷 원본 | 팀 1차 |
| --- | --- | --- |
| 함수를 부르는 주체 | 삐 소리 서버의 `--demo-tool`. 발신자 정보가 있을 때 고정 인자(`DEMO1001`)로 1회 | LLM이 대화 내용을 보고 판단 |
| 일치하는 입력 | `not_implemented`, matched=false | 기록된 결과, matched=true |
| 데이터가 없는 입력 | `not_implemented` | `not_found` (문구는 예제용 선택) |
| 정의되지 않은 함수 | 404, 호출 기록에 남지 않음 | 404 + 기록(`known:false`). 상담원 서버는 이런 호출을 애초에 보내지 않음 |
| 실패·시간 초과 | 처리 없음 | `status:error`로 바꿔 LLM에 전달해, 모델이 성공으로 오인하지 않게 함 |
| `tools_url`, `X-Session-Id` | 세션 값 사용 | 세션 값 사용. 서로 다른 `tools_url` 2개로 나눈 동시 4세션 테스트 통과 |
| 세트 B 측정 결과 (gpt-4.1) | 호출 0 | 호출 16, 일치 12. 불일치 4 = 의도된 not_found 3 + LLM이 `DEMO10001`로 잘못 입력한 1 |

- 원본 기록은 2026-11-19 세트 A `--demo-tool` 3회 측정 기준입니다(호출 3, 일치 0).
- 공식 환경에서는 함수 중계가 호출을 기록합니다. `GET /calls`는 스타터킷 측정기 호환용입니다. 매칭 규칙(공백·하이픈·대소문자 무시)도 예제용 선택입니다.

## 팀 1차 지연과 응대 내용

첫 소리까지의 시간은 세 단계가 각각 1초 안팎씩 차지합니다: 발화 종료 판단, LLM, 첫 문장 TTS. 모델 간 차이는 거의 LLM 단계에서 생깁니다.

**첫 소리까지의 단계별 시간** (마지막 음성 기준, 단계별 p50, 세트 B 24회씩)

| 모델 | 발화 종료 판단 | LLM 첫 텍스트 | 첫 문장 TTS·전송 | 합계 |
| --- | --- | --- | --- | --- |
| gpt-4.1 | 1.15 s | **1.15 s** | 0.93 s | 3.23 s |
| gpt-4o-mini | 1.14 s | **1.29 s** | 1.20 s | 3.62 s |
| gpt-5 | 1.11 s | **1.76 s** | 1.15 s | 4.02 s |

- 원자료는 `team/runs/fixed_*`의 에이전트 지표(2026-11-18 측정)입니다.
- 데모 점수표 100점 기준은 1.5s입니다. 발화 종료 판단과 LLM 두 단계만 더해도 이를 넘습니다.
- STT는 무음 400ms 시점에 미리 요청해 발화 종료 판단 전에 끝납니다(판단 후 대기 0ms). 그래서 표에 따로 나타나지 않습니다.
- 함수를 호출하는 문항은 LLM을 두 번 부르므로 더 느립니다. 단계별 p50을 더한 합계는 전체 p50과 조금 다를 수 있습니다.

**응답 내용 관찰** (세트 B, 문항당 3회. 응답 텍스트를 직접 읽고 판정)

| 항목 | gpt-4.1 | gpt-4o-mini | gpt-5 |
| --- | --- | --- | --- |
| 주문 조회 결과 반영 (K01·K03·K04·K08) | 11/12 | 10/12 | 11/12 |
| 없는 주문번호(K02)에 "일치 내역 없음" 안내 | 3/3 | 3/3 | 3/3 |
| 콜백 전 번호 확인 (K07) | 3/3 | 3/3 | **0/3**: 확인 없이 접수했고, 인자에 없는 "내일 오전"도 접수됐다고 말함 |
| 인계 후보 (K06) | 연결 약속 없음. "복용 중단" 지시 1/3 | 연결 약속 없음. 의료기관 권유 없음 | 연결 약속 없음. 119 안내 1/3 |

- 조회 실패는 두 종류입니다. STT가 "1001이에요"를 `10012`로 붙여 쓴 경우와, LLM이 `DEMO10001`로 잘못 입력한 경우입니다. 두 경우 모두 결과를 지어내지 않고 "일치 내역 없음"으로 안내했습니다.
- 스타터킷 데모 음성(gpt-4.1)에서는 문제가 하나 있었습니다. DEMO3 반품 포장 문의에 "다른 박스에 포장하셔도 괜찮지만"처럼 **매뉴얼에 없는 업무 조건을 안내**했습니다.
  같은 세트에서 DEMO2 복용법 문의는 안내를 거절했고, DEMO1은 불완전한 전화번호를 다시 확인했습니다.

## 스타터킷에서 발견한 이상

스타터킷 데모 음성 3개는 README 설명과 다르고, `meta.json`의 발화 종료 시각도 실제 음성과 맞지 않습니다. 어느 쪽이 의도인지는 운영진 확인이 필요합니다.

| 파일 | 길이 | `speech_end` | 실제 음성 (STT) | `demo_cases.jsonl` 문장 |
| --- | --- | --- | --- | --- |
| DEMO1.wav | 8.3 s | 3.087 s | 한국어 "카드 사용이 어렵네요. 임서재 010…" | Hello, what time do you open? |
| DEMO2.wav | 3.65 s | 5.337 s (파일보다 김) | 한국어 "효과적인 복용 방법은 무엇입니까?" | My order number is demo one zero zero one… |
| DEMO3.wav | 9.3 s | 2.77 s | 한국어 "택배 상자가 없어서… 반품이라고 적어서 내놓으면 되겠죠?" | Please call me back tomorrow. |

- README는 "영어 합성음"이라고 설명하지만, 세 파일 모두 한국어입니다.
- DEMO1·DEMO3은 `speech_end` 뒤에도 음성이 5~6초 이어집니다. 그래서 어느 서버든 첫 소리가 6~9초로 기록됩니다.
- DEMO2는 `speech_end`가 파일 끝보다 뒤라서, 정상적으로 답해도 "끼어듦"으로 판정될 수 있습니다. 원본은 3회 모두 끼어듦으로 기록됐습니다.
- Windows에서 `run_eval.py`로 한글 케이스 파일을 읽으려면 `PYTHONUTF8=1`이 필요합니다. 측정기가 파일을 열 때 인코딩을 지정하지 않기 때문입니다.

## 한계와 다음 단계

이 비교는 팀이 만든 합성 음성 8문항에 기대고 있어, 공식 문항에서의 성능을 보장하지 않습니다.

- **과적합 가능성**: 연습용 프롬프트를 이 8문항의 응답을 보며 고쳤습니다. 응답 판정도 사람이 텍스트를 읽고 매긴 것입니다.
- **음성 품질**: 깨끗한 합성음이라 실제 고객 목소리나 전화망 음질보다 STT에 유리합니다.
- **외부 전송**: 팀 1차는 고객 음성, 인식 텍스트, 발신자 정보를 OpenAI로 보냅니다. 대회 자료를 외부로 보내도 되는지는 아직 정해지지 않았습니다.
- **남은 끼어듦**: 완결된 문장 뒤 1.1초 넘게 쉬면 여전히 끼어듭니다(K05). 무음만으로 1.5초를 기다리면 끼어듦은 사라지지만, 첫 소리가 더 늦어집니다.
