# 음성 테스트 화면 (팀 내부 개발 도구)

팀원이 브라우저에서 직접 말하고 상담원 응답을 들으며 상담 흐름을 확인하는 **로컬 테스트 도구**입니다.
고객용 서비스나 운영진 측정기가 아닙니다. 이 화면에서 잰 시간은 공식 측정값과 같지 않습니다.

## 실행

저장소 루트에서 터미널 2개를 엽니다.

```bash
# A. 모의 함수 서버
.venv/Scripts/python -m team.mock.mock_api --port 8100

# B. 테스트 서버 (화면 + 디버그 WebSocket). 저장소 루트의 .env에서 OPENAI_API_KEY를 읽음
.venv/Scripts/python -m team.devui.server            # → http://127.0.0.1:9100
#   키 없이 흐름만 볼 때 (AI가 아닌 테스트 대체물):
.venv/Scripts/python -m team.devui.server --llm scripted --tts tone
#   발화 종료 설정 바꿔 보기:
.venv/Scripts/python -m team.devui.server --complete-silence-ms 900 --max-silence-ms 1600
```

브라우저(Chrome/Edge 권장)에서 **http://127.0.0.1:9100** 또는 **http://localhost:9100**을 엽니다.
브라우저는 localhost나 HTTPS 주소에서만 마이크를 허용합니다. 다른 PC에서 IP 주소로 접속하면 마이크가 동작하지 않습니다.

테스트 서버는 대회용 서버(`team.agent.server`)와 **같은 Session·Dialog·ToolsClient 코드와 같은 설정(`AGENT_*` 환경 변수)**을 씁니다.
서로 다른 점은 다음뿐입니다.
- 포트가 9100이고, 127.0.0.1에서만 접속을 받습니다.
- 디버그 이벤트를 보냅니다.
- 시간 기록 파일이 `team/runs/devui_metrics.jsonl`입니다.

## 마이크가 안 잡힐 때

- **처음에는 맨 위의 "마이크 자동 찾기"를 누릅니다.** 모든 입력 장치를 동시에 열고, 1.5초 조용히 있을 때와 3초 말할 때의 레벨을 비교해 목소리가 가장 크게 바뀌는 장치를 골라 저장합니다(서버 연결 없음, 음성 저장 없음).
  - 장치 비교는 브라우저 처리(자동 음량·잡음 억제·에코 제거)를 끈 원래 신호로 합니다. 자동 음량은 조용할 때 잡음을 키우고 말할 때 줄여서 차이를 좁힙니다.
  - 판정: 소리 없음(연결 안 됨·음소거) / 말해도 레벨 변화 없음(1.5배 미만, 잡음만) / 약하게 감지(1.5~2배) / 목소리가 너무 작음 / 목소리 감지(2배 이상)
  - 뚜렷한 장치가 없으면 약하게 감지된 장치 중 가장 가능성 높은 것을 경고와 함께 고릅니다. 표의 "이 장치 쓰기"로 직접 바꿀 수 있습니다.
  - 목소리가 들어오는 장치가 하나도 없으면 아무것도 고르지 않고 확인할 곳을 안내합니다.
  - 고른 장치는 다음에 페이지를 열 때도 씁니다. 그 장치가 빠지면 상태 줄에 알리고 시스템 기본 장치를 씁니다.
- 직접 고르려면 설정 카드의 **마이크 장치**에서 선택합니다. 장치 이름은 마이크 권한을 한 번 허용한 뒤에 보입니다.
- **마이크 점검 (4초)**: 서버에 연결하지 않고, 1.5초 조용히 있을 때와 2.5초 말할 때의 레벨을 비교해 판정합니다.
  - "소리가 거의 들어오지 않음" → 연결되지 않은 장치이거나 음소거
  - "말할 때와 조용할 때 차이가 거의 없음" → 잡음만 들어오는 장치 (자동 음량이 잡음을 키움). 다른 장치 선택
  - "목소리가 작음" → 마이크에 가까이, 또는 Windows 입력 음량 올리기
- "음성 입력 점검" 카드의 **사용 중인 마이크**에 실제로 연 장치 이름이 나옵니다.
- 장치 목록이 비어 있으면 Windows 설정 → 개인 정보 → 마이크에서 데스크톱 앱(브라우저)의 마이크 접근을 확인합니다.
- 잡음만 들어간 음성을 로컬 Whisper가 받으면 "한글자막 by …" 같은 자막 문구를 지어냅니다. 이 문구는 버리고 "잘 듣지 못했습니다"로 답하게 했습니다.

## 시험 순서
## 시험 순서

1. 설정 카드에서 `tools_url`(기본 `http://127.0.0.1:8100`)과 `now`를 확인합니다. 필요하면 `caller`와 `history`도 넣습니다.
2. **테스트 시작**을 누르고 마이크 권한을 허용합니다.
3. 상태가 "마이크 전송 중 · 말씀하세요"가 되면 고객처럼 한 번 말하고 기다립니다.
   - 서버가 음성을 감지하면 "고객 음성 수신 중 (서버 VAD 감지)"으로 바뀝니다.
   - 서버가 발화 종료를 확정하면 "발화 종료 확정 · 응답 준비 중"으로 바뀌고, 판정 사유와 무음 길이가 표시됩니다.
   - `turn.end`를 받을 때까지 마이크 음성(무음 포함)을 계속 보냅니다. 측정기처럼 서버가 직접 발화 종료를 판단하게 하기 위해서입니다.
4. 응답 음성이 재생됩니다. "서버 응답 완료 (turn.end)"와 "응답 음성 재생: 재생 완료"는 따로 표시됩니다.
   응답 음성이 한꺼번에 전송되므로(burst), 보통 `turn.end`가 재생 완료보다 먼저 옵니다.
5. **내가 한 말**이 텍스트로 표시됩니다(서버 STT 인식 결과).
   - 말하다 잠깐 쉬면 서버가 미리 인식한 결과가 바로 나타나고, `미리 인식 · 확정 전` 표시가 붙습니다.
   - 말을 이어서 하면 그 인식 결과는 버려지고 다시 인식합니다.
   - 발화 종료가 확정되면 `확정 · 응답에 사용`으로 바뀝니다. 이 텍스트가 실제로 LLM에 들어간 문장입니다.
   - 테스트마다 고객 발화와 상담원 응답이 아래 **지난 테스트 기록**에 쌓입니다. **기록 복사**로 클립보드에 복사할 수 있습니다.
   - 호환 모드에서는 대회용 서버가 인식 결과를 보내지 않으므로 표시되지 않습니다.
6. 함수 호출(인자·결과·함수 서버 기록 대조)과 시간 표를 확인합니다.
7. 다음 턴을 이어서 시험하려면 **방금 결과를 history에 추가**를 누르고 다시 **테스트 시작**을 누릅니다. 테스트마다 새 세션과 새 연결을 만듭니다.

### 직접 시험해 볼 상황
- **긴 쉼**: "주문번호가 … (1~2초 쉼) … 데모 일공공일이에요". 쉬는 동안 말이 끊겼다고 판정되는지, `resume`(말 이어짐)으로 처리되는지 확인합니다.
- **숫자 정정**: "데모 일공공일, 아니 일공공이요". 함수 호출 카드에서 실제로 보낸 `order_id`를 확인합니다.
- **조용한 환경과 시끄러운 환경**: 마이크 레벨 막대와 빨간 기준선을 비교합니다. 기준선은 브라우저의 발화 추정 기준이며, 서버의 에너지 하한은 "서버" 줄에 표시됩니다.
- **보낸 음성 다시 듣기**: 서버로 보낸 16 kHz 변환 음성을 그대로 다시 들어 봅니다. 음성은 메모리에만 있으며 파일로 저장하지 않습니다.

## 연결 모드

| 모드 | URL | 받는 정보 |
|---|---|---|
| 테스트 서버 `/ws` (기본) | `ws://127.0.0.1:9100/ws` | 공식 메시지 + `debug.*` (VAD, 발화 종료, STT, LLM 라운드, 함수 인자·결과, 서버 시각, 함수 서버 `/calls` 기록) |
| 호환 모드 | `ws://127.0.0.1:9000` (대회용 서버) | 측정기가 받는 것과 같음: PCM, `agent.transcript`, `turn.end` |

호환 모드에서는 서버의 내부 판단(음성 감지, 발화 종료, 인식 텍스트, 함수 호출)을 받을 수 없어 "제공 안 됨"으로 표시합니다.
이 모드는 대회용 서버가 측정기에 실제로 보내는 메시지를 눈과 귀로 확인하는 용도입니다.
화면 파일은 테스트 서버(9100)에서 열고, URL만 9000으로 바꿉니다.

## 대회 측정기 호환성

- 대회용 진입점 `python -m team.agent.server`의 동작과 메시지 형식은 바뀌지 않았습니다.
  - `Session`, `Dialog`, `ToolsClient`에 `debug` 속성(기본 `None`)만 추가했습니다. `None`이면 디버그 코드가 실행되지 않고 아무것도 보내지 않습니다.
  - 대회용 서버는 이 속성을 설정하지 않습니다.
- 디버그 이벤트는 `team.devui.server`의 `/ws` 경로에서만 나갑니다. 테스트 서버의 다른 경로로 들어오는 WebSocket은 404로 거절합니다.
- 확인 방법(2026-11-19 실행)은 다음과 같습니다.
  - pytest `team/tests/test_devui.py::test_competition_path_sends_no_debug_events`
  - 원본 `eval/run_eval.py`로 연습 8문항을 변경 전 코드와 변경 후 코드에서 각각 실행했습니다(테스트 대체물 사용). 응답 텍스트, 함수 호출, 끼어듦, `turn.end`가 같았습니다.

## 시간 표 읽는 법

| 열 | 기준점(0 ms) | 시계 |
|---|---|---|
| 서버 기록 | 서버 VAD가 판정한 **마지막 음성 프레임 도착** | 서버 |
| 브라우저 관측 | 브라우저가 레벨(int16 RMS ≥ 기준값)로 **추정**한 마지막 음성 | 브라우저 |

- 두 시계는 서로 빼지 않습니다. 서버 이벤트 줄의 브라우저 열 값은 그 디버그 이벤트를 **받은 시각**입니다.
- "브라우저 첫 재생 시작"은 Web Audio에 예약한 시각에 `outputLatency`(지원 시)를 더한 추정치입니다. 실제 스피커 출력 시각은 측정하지 않습니다.
- 운영진 측정기는 녹음 파일 안의 **정해진 발화 끝 시각**을 기준으로, 받은 음성 중 **첫 유음 프레임**까지를 잽니다(`eval/run_eval.py`). 이 화면의 값과는 기준점과 측정 위치가 다릅니다.
- 브라우저 열은 다음 때문에 오차가 생깁니다: 마이크 입력 지연, 에코 제거 같은 브라우저 처리, 기준값 설정.

## history 형식

공식 `session.start.history` 형식(11/21 공식 자료 `SPEC.md`)은 네 종류 항목의 목록입니다.
`{"role":"customer","text":...}`, `{"role":"agent","text":...}`, `{"role":"tool_call","name":...,"arguments":{...}}`, `{"role":"tool_result","name":...,"result":{...}}`

- 서버(`team/agent/policy.py`의 `normalize_history`)는 이 형식을 읽어 "고객:/상담원:/(함수 호출)/(함수 결과)" 줄로 바꿔 프롬프트에 넣고, 실행 전 관문도 이 안의 번호를 "이미 나온 정보"로 봅니다. 예전 `user`/`assistant`도 고객/상담원으로 읽습니다.
- 개발 화면의 **방금 결과를 history에 추가**는 아직 `user`/`assistant` 두 줄만 넣고 함수 기록은 넣지 않습니다.
- 시연 화면(`?demo=1`)은 끝난 턴을 공식 형식(함수 호출·결과 포함)으로 다음 연결에 넘깁니다.
- 시연 화면 오른쪽은 탭 세 개입니다. **처리**: 조회·접수 기록과 응답 시간. **점수**: 이번 통화의 턴별 속도 점수, 공식 속도 점수표(이번 턴 위치 굵게), 시스템 점수 구성. **기록**: 서버가 잰 단계별 걸린 시간(고객 말이 끝난 뒤부터: 말 끝 판단, 받아쓰기, 답 첫 글자, 첫 문장 합성, 첫 소리, 응답 끝)과 이번 턴의 진행 단계를 시간순으로 보여 주고 복사할 수 있습니다. **전체**(기본)는 서버가 보낸 단계를 모두(잠깐 멈출 때마다의 미리 받아쓰기, 관문 통과, 답 만들기 끝 포함), **요약**은 주요 단계만 보여 줍니다. 고른 보기는 브라우저에 기억됩니다. 개발 화면의 이벤트 기록·시간 표는 그대로 둡니다.

## 오류와 정리

| 상황 | 표시 | 정리 |
|---|---|---|
| 마이크 권한 거부, 장치 없음, 장치 사용 중 | 원인별 안내 | 열었던 자원 닫음 |
| localhost나 HTTPS가 아닌 주소 | 주소 안내 | — |
| 연결 실패, 5초 연결 시간 초과 | 서버 실행 여부와 URL 확인 안내 | WebSocket 닫음 |
| `turn.end` 전에 연결 끊김 | close code 표시 (1002 = session.start 거부) | 전체 정리 |
| 응답 시간 초과 | 발화 종료 확정(없으면 브라우저 추정 발화 끝) 뒤 25초 안에 `turn.end` 없음(스타터 측정기와 같은 25초). 테스트 전체 120초 상한 | 전체 정리 |
| 오디오 변환 실패 (AudioWorklet), 재생 실패 | 오류 상태 | 전체 정리 |
| 중지 버튼, 새 테스트 시작, 페이지 닫기 | — | 전체 정리 |

- "전체 정리"에서는 마이크 트랙, 오디오 노드, AudioContext, 타이머, WebSocket을 닫습니다. 각 자원의 상태는 "음성 입력 점검 → 자원 상태"에서 확인합니다.
- `turn.end`를 받으면 마이크는 바로 끄고, 남은 응답 음성은 끝까지 재생합니다. 디버그 모드에서는 시간 기록과 함수 서버 기록을 최대 3초 더 기다린 뒤 연결을 닫습니다.

## 개인정보·데이터 취급 (실제 대회 데이터를 쓰기 전에 확인)

- **음성**: 브라우저 메모리에만 있습니다(다시 듣기용, 최대 30초). 파일로 저장하지 않으며 새 테스트를 시작하거나 페이지를 닫으면 사라집니다. 서버도 음성을 저장하지 않습니다.
- **디버그 이벤트**: 인식 텍스트, 상담원 응답, 함수 인자와 결과(주문·회원 정보가 들어갈 수 있음)를 이 화면에만 보냅니다.
  - 서버 기록 파일 `team/runs/devui_metrics.jsonl`에는 시간 값만 남습니다. `AGENT_LOG_TEXT=1`을 켜면 텍스트도 남습니다.
  - 이 파일은 `.gitignore`에 등록되어 있습니다.
- **지난 테스트 기록**(인식 텍스트와 응답): 페이지 메모리에만 있고, 새로고침하면 사라집니다. 기록 복사는 사용자가 버튼을 누를 때만 클립보드로 복사합니다.
- **브라우저 저장소**: localStorage에는 연결 모드, URL, 마이크 옵션, 기준값만 저장합니다. `caller`와 `history`는 저장하지 않습니다.
- **외부 전송**: 실제 OpenAI 공급자를 쓰면 고객 음성(STT), 인식 텍스트, `caller`, `history`가 OpenAI로 전송됩니다(대회용 서버와 같음).
- 실제 대회 데이터의 표시, 보관, 외부 전송 허용 범위는 **운영진 안내가 우선**하며, 아직 확인하지 못했습니다. 확인 전에는 연습용 가상 데이터만 쓰세요.
- 테스트 서버는 기본적으로 127.0.0.1에만 열립니다. `--host 0.0.0.0`으로 열면 같은 네트워크의 누구나 디버그 정보를 볼 수 있습니다.

## 디버그 이벤트 목록 (`/ws`에서만 전송)

모든 이벤트에는 `t_ms`(서버가 `session.start`를 받은 시점부터 잰 ms, 서버 시계)가 붙습니다.

| type | 내용 |
|---|---|
| `debug.hello` | 서버 종류와 공개 설정(모델명, 발화 종료 임계값 등). API 키는 들어가지 않음 |
| `debug.session` | session_id, tools_url, history 길이, caller 유무 |
| `debug.tools` | `GET /tools`로 받은 함수 이름 목록과 오류 |
| `debug.vad` | `speech_start`, `resume`(말 이어짐), `speculative_stt_start` |
| `debug.stt` | STT 결과(미리 실행한 것 포함), 소요 ms |
| `debug.eou` | 발화 종료 확정 사유, 발화 길이, 무음 길이, 마지막 음성 시각, 확정 시각 |
| `debug.stt.final` | 응답에 실제로 사용한 고객 발화 텍스트 |
| `debug.llm.round_start` / `first_text` / `round_end` | LLM 라운드, 첫 텍스트, 라운드별 텍스트와 함수 요청 |
| `debug.tool.start` / `tool.end` | 함수 이름, 인자(원문 JSON), 결과, 소요 ms, 실제 전송 여부, HTTP 상태 |
| `debug.gate` | 실행 전 관문 판정: 함수 이름, 허용 여부, 차단 사유, 인자(내부 동의 칸 제외), 모델에게 돌려준 안내. **막힌 호출은 함수 서버로 가지 않아 `tool.start`가 없으므로 이 이벤트로만 보임** |
| `debug.blocked_reply` | 모두 막힌 라운드 뒤 응답 방식: `already_asked` / `template`(규칙 파일의 확인 문장) / `model` |
| `debug.output_guard` | 출력 검사 표시: 근거 없는 숫자(`log`면 기록만, 문장은 그대로 말함) 또는 같은 턴 반복 문장(버림) |

| `debug.eou_mode` / `debug.soniox` | `AGENT_EOU_MODE=soniox_stream`일 때: 이번 세션의 실제 모드, Soniox `<end>` 수신·무시, 이어 말함 |
| `debug.audio.first_sent` | 첫 음성 데이터 전송 |
| `debug.turn_end_sent` | `turn.end` 전송과 결과(outcome) |
| `debug.metrics` | 서버 metrics 한 줄과 고객 발화, 응답 텍스트 |

## 평가 기준 · 예상 점수 카드 (연습용, 공식 점수 아님)

대회 시스템 점수 규칙(응대 50% + 함수 20% + 속도 30%, 100점 → ÷ 5 = 20점 항목)으로 테스트마다 예상 점수를 계산합니다.

| 항목 | 계산 방식 |
|---|---|
| 속도 (자동, **추정**) | 발화 끝 → 받은 응답 음성 중 첫 소리(20 ms 조각 RMS 300 이상, 측정기와 같은 기준)까지의 시간을 첫 소리 표(1.5초 이하 100점 … 6초 초과 0점)로 점수화. 함수를 함수 서버로 실제로 보낸 테스트는 (첫 소리 점수 + 마지막 함수 결과 뒤 첫 소리를 조회 뒤 답 표(3.5초 이하 100점 … 8초 초과 0점)로 매긴 점수) ÷ 2. 두 표는 공식 `eval/score.py`와 같음 |
| 0점 처리 | 응답 소리 없음, 연결 실패·응답 없음, 끼어듦 의심(응답 첫 소리가 도착할 즈음 마이크에 말소리가 있었음, 브라우저 추정) |
| 응대·함수 (직접 판정) | 정답표가 없어 표에서 맞음/괜찮음/틀림을 고르면 계산. 함수 칸 아래에 실제로 보낸 호출과 관문에 막힌 호출을 보여 줌 |
| 사용자 경험 50점 | 정성 평가라 기준만 보여 주고 계산하지 않음 |

- 발화 끝 기준점: 테스트 서버 /ws에서는 서버 VAD의 마지막 음성 프레임, 호환 모드에서는 브라우저 레벨 추정. 공식 측정은 녹음 파일에 정해진 발화 끝 시각을 쓰므로 값이 다를 수 있습니다.
- 판정하지 않은 테스트는 속도 부분(30점 중)만 보이고 평균에서 빠집니다. 기록은 페이지 메모리에만 있고 "기록 지우기"나 새로고침으로 사라집니다.
- 정확한 속도는 공식 측정기와 채점기(`eval/run_eval.py` + `eval/score.py`)로 확인합니다.

## 한계와 후속 개선

- 한 연결에 고객 발화 한 번만 다룹니다. 끼어들기(barge-in)나 연속 통화는 다루지 않습니다. 서버도 응답 중 입력은 무시합니다(half-duplex).
- 이 PC에서는 브라우저 실기 시험(마이크 권한, 실제 재생 순서와 끊김, 장치별 샘플레이트)을 하지 못했습니다. 위 "시험 순서"대로 확인이 필요합니다.
- Safari와 Firefox에서 AudioWorklet 모듈 import가 되는지 확인하지 않았습니다. Chrome과 Edge를 먼저 쓰세요.
- 응답 음성 전송 방식이 `realtime` pacing이면 `turn.end`와 재생 완료 시점이 가까워집니다(`AGENT_OUTPUT_PACING`).
- 가능한 후속 작업:
  - 연습 wav 파일을 화면에서 골라 보내기(마이크 대신)
  - 시험 결과 여러 건 비교 표
  - 개발 화면의 "방금 결과를 history에 추가"도 공식 형식(함수 호출·결과 포함)으로 맞추기
